POST INTERACTION FLOW (IMPLEMENTED)
============================================================

1) LIKE FLOW

Client
  POST /api/v1/post-likes/:postId
  │
  ▼
postLike.route -> authMiddleware -> postLike.controller.likePost
  │
  ▼
postLike.service.likePost(userId, postId)
  │
  ├── (A) postLike.repository.likePost (DB transaction)
  │       ├── check existing like by (user_id, post_id)
  │       ├── if already liked -> return liked=false
  │       ├── INSERT post_likes(user_id, post_id)
  │       └── UPDATE posts SET like_count = like_count + 1
  │
  └── (B) if liked=true, enqueue 2 background jobs
      │
      ├── (B1) enqueueUserInteraction(userId, postId, 'like', tags)
      │    │
      │    ▼
      │      BullMQ queue: user-interaction
      │    │
      │    ▼
      │      user-interaction.worker -> user-interaction.processor
      │    ├── INSERT user_interactions(user_id, post_id, type, tag_snapshot)
      │    └── Redis HINCRBYFLOAT user:interest:<userId> <tag> +1.0
      │
      └── (B2) enqueuePostCacheRefresh(postId, trigger='like')
           │
           ▼
             BullMQ queue: post-cache-refresh
           │
           ▼
             post-cache-refresh.worker -> post-cache-refresh.processor
           ├── getFeedCacheDataByPostIds([postId]) from DB
           ├── if post exists -> cachePostCacheDataBatch([post]) to Redis post:data:{postId}
           └── if post missing -> DEL Redis post:data:{postId}


2) UNLIKE FLOW

Client
  DELETE /api/v1/post-likes/:postId
  │
  ▼
postLike.route -> authMiddleware -> postLike.controller.unlikePost
  │
  ▼
postLike.service.unlikePost(userId, postId)
  │
  ├── (A) postLike.repository.unlikePost (DB transaction)
  │       ├── check existing like by (user_id, post_id)
  │       ├── if not liked -> return unliked=false
  │       ├── DELETE FROM post_likes WHERE user_id = ? AND post_id = ?
  │       └── UPDATE posts
  │             SET like_count = CASE WHEN like_count > 0 THEN like_count - 1 ELSE 0 END
  │
  └── (B) if unliked=true, enqueuePostCacheRefresh(postId, trigger='unlike')
      │
      ▼
        BullMQ queue: post-cache-refresh
      │
      ▼
        post-cache-refresh.worker -> post-cache-refresh.processor
      ├── getFeedCacheDataByPostIds([postId]) from DB
      ├── if post exists -> cachePostCacheDataBatch([post]) to Redis post:data:{postId}
      └── if post missing -> DEL Redis post:data:{postId}

NOTE:
- Unlike does NOT enqueue user-interaction event (interest score is not decreased realtime).
- Unlike now DOES enqueue post-cache-refresh to keep feed like_count close to DB.

============================================================
DATA OWNERSHIP
============================================================

Redis:
- user:interest:<userId> (realtime ranking signal)

Database:
- post_likes: source of truth for like/unlike state
- comments: source of truth for comments
- user_interactions: durable interaction history for analytics/rebuild

Rebuild path when Redis miss/restart:
- Query interaction history from DB
- Aggregate per tag
- Call postRedisService.rebuildFromDB(userId, interests)

POST DELETE FLOW (SYNC SHORT + ASYNC CLEANUP)
============================================================

1) API ENTRY

Client
  DELETE /api/v1/posts/:postId
  │
  ▼
post.route -> authMiddleware -> post.controller.deletePost
  │
  ▼
post.service.deletePost(userId, postId)


2) DB TRANSACTION (SHORT)

service loads delete candidate:
- post exists?
- authorId check (owner only)
- collect media URLs for cleanup payload

transaction delete order:
1. post_likes
2. comments
3. post_hashtags
4. post_media
5. posts

commit immediately after DB delete success.


3) ASYNC CLEANUP QUEUE

after commit, enqueue post-delete-cleanup job:
- postId
- authorId
- media[]
- deletedAtIso

if enqueue fails:
- log attempt 1
- retry enqueue once
- keep response successful (DB already committed)


4) WORKER CLEANUP

post-delete worker:
- DEL post:data:{postId}
- getFollowerIdsByUserId(authorId)
- batch ZREM postId from feed:{authorId} + follower feeds
- Cloudinary destroy for each media URL (best-effort)
- on final failure push to DLQ


5) READ SELF-HEAL

If some feed keys still contain stale postId before cleanup finishes,
getFeed fallback path removes orphan ids when post data is missing,
so system remains eventually consistent.


Mermaid Diagram:

```mermaid
flowchart TD
    A[Client DELETE postId] --> B[Auth Middleware]
    B --> C[Post Controller Validate]
    C --> D[Post Service Authorize]
    D --> E[(DB Transaction)]
    E --> E1[Delete post_likes]
    E1 --> E2[Delete comments]
    E2 --> E3[Delete post_hashtags]
    E3 --> E4[Delete post_media]
    E4 --> E5[Delete posts]
    E5 --> F[Commit]
    F --> G[Enqueue post-delete-cleanup]
    G --> H[[BullMQ Worker]]
    H --> I[DEL post:data:postId]
    H --> J[Batch ZREM postId from feeds]
    H --> K[Cloudinary destroy media]
    H --> L{Failed after retries?}
    L -- Yes --> M[(DLQ)]
    L -- No --> N[Done]
```

UNFOLLOW FLOW (ARROW STYLE)
============================================================

Client
  DELETE /api/v1/follow
  body: { targetUserId }
  │
  ▼
follow.route -> authMiddleware -> follow.controller.unfollow
  │
  ▼
follow.service.unfollow(currentUserId, targetUserId)
  │
  ├── (A) Guard + Validate
  │       ├── target ids must be valid numbers
  │       ├── cannot unfollow yourself
  │       └── ensure currentUser + targetUser exist
  │
  ├── (B) DB Transaction (atomic)
  │       ├── DELETE follows WHERE follower_id=currentUserId AND following_id=targetUserId
  │       ├── DELETE follow_requests WHERE requester_id=currentUserId AND target_user_id=targetUserId AND status='pending'
  │       └── branch result
  │            ├── if follow deleted -> mode='unfollowed'
  │            ├── else if pending request deleted -> mode='cancelled_request'
  │            └── else -> NotFoundError('Follow relationship not found')
  │
  ├── (C) Redis count cache invalidation
  │       ├── DEL follow:count:followers:{currentUserId}
  │       ├── DEL follow:count:following:{currentUserId}
  │       ├── DEL follow:count:followers:{targetUserId}
  │       └── DEL follow:count:following:{targetUserId}
  │
  └── (D) Feed cleanup only when mode='unfollowed'
      │
      ├── (D1) Sync cleanup (best-effort)
      │       ├── getAllFeedPostIds(viewerUserId)
      │       ├── getPostAuthorIdsByPostIds(feedPostIds)
      │       └── removePostIdsFromFeed(viewerUserId, postsOfTargetAuthor)
      │
      └── (D2) Async cleanup queue (fallback)
          ├── enqueueUnfollowFeedCleanup(viewerUserId, targetAuthorId, unfollowedAtIso)
          ├── BullMQ worker: unfollow-feed-cleanup.worker
          ├── processor re-runs cleanup logic
          └── failed after retries -> push DLQ (unfollow-feed-cleanup-dlq)


Return Response
  ├── mode='unfollowed', followStatus='none'
  └── mode='cancelled_request', followStatus='none'

UPDATE POST HASHTAG + LOCATION FLOW (ARROW STYLE)
============================================================

Client
  PATCH /api/v1/posts/:postId
  body: { caption?, location?, tags? }
  │
  ▼
post.route -> authMiddleware -> post.controller.updatePost
  │
  ▼
post.service.updatePost(userId, postId, payload)
  │
  ├── (A) Controller Validate Input
  │       ├── postId must be positive number
  │       ├── tags must be string[] if provided
  │       ├── caption must be string if provided
  │       └── location must be string if provided
  │
  ├── (B) Service Guard + Ownership
  │       ├── at least one field required: caption | location | tags
  │       ├── getPostOwnerId(postId)
  │       ├── post not found -> NotFoundError
  │       └── owner mismatch -> ForbiddenError (only owner can update)
  │
  ├── (C) Normalize Payload
  │       ├── load current post detail + current tags
  │       ├── normalizeOptionalText(caption, max=2200)
  │       ├── normalizeOptionalText(location, max=255)
  │       ├── normalizeTags(tags)
  │       │    ├── trim + lowercase
  │       │    ├── remove prefix '#'
  │       │    ├── drop empty tags
  │       │    ├── max 20 tags
  │       │    ├── each tag max length 50
  │       │    └── deduplicate
  │       └── empty text after trim -> null
  │
  ├── (D) DB Transaction Update Metadata + Hashtag Mapping
  │       ├── UPDATE posts
  │       │    ├── set caption
  │       │    ├── set location
  │       │    └── set updated_at = CURRENT_TIMESTAMP
  │       ├── DELETE post_hashtags WHERE post_id=:postId
  │       ├── if tags empty -> stop mapping step
  │       ├── INSERT hashtags (name) with orIgnore
  │       ├── SELECT hashtag ids by names
  │       └── INSERT post_hashtags(post_id, hashtag_id)
  │
  ├── (E) Cache Refresh (best-effort)
  │       ├── getFeedCacheDataByPostIds([postId]) from DB
  │       ├── cachePostCacheDataBatch([postCacheData]) to Redis hash post:data:{postId}
  │       └── if refresh fail -> log only, request still success
  │
  └── (F) Build Response
          ├── reload updated post detail
          ├── reload tags by post id
          └── return { id, caption, location, tags, created_at }


Quick Branches:
- payload has no caption/location/tags -> 400 BadRequest
- invalid location type or tags type -> 400 BadRequest
- postId not found -> 404 NotFound
- user is not post owner -> 403 Forbidden
